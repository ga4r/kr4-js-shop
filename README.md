# RunSmart — интерактивная версия

## Контрольная работа №4

Тема: «JavaScript: интерактивность, DOM, события, формы и валидация».

Магазин пульсометров RunSmart, в который добавлена интерактивность на чистом JavaScript: каталог строится из массива товаров, работают поиск, фильтр и сортировка, есть корзина и проверка формы заявки. Библиотеки и фреймворки не используются.

**Основа проекта:** КР №3 `kr3-responsive-shop` (адаптивная HTML/CSS-версия магазина). Вёрстка, стили и адаптив взяты оттуда, добавлены JavaScript, страница корзины и стили для новых блоков.

## Как запустить

- Онлайн — по ссылке выше.
- Локально — открыть `index.html` в браузере или запустить через Live Server в VS Code. Сборка не нужна: скрипты подключены обычными тегами `<script>` в конце `<body>`, без модулей, поэтому сайт работает и при открытии файла напрямую.

## JavaScript-файлы

Файлы подключаются на каждой странице в таком порядке: `data.js` → `catalog.js` → `cart.js` → `modal.js` → `validation.js` → `main.js`.

- `data.js` — массив товаров `products` и объект `categoryNames` с русскими названиями категорий.
- `catalog.js` — создание карточки товара (`createProductCard`), вывод списка (`renderProducts`), сортировка копии массива (`sortProducts`), логика страницы каталога (`initCatalog`), популярные товары на главной (`renderPopularProducts`) и похожие товары на странице товара (`renderSimilarProducts`). Здесь же вспомогательная функция `makeElement`: создаёт элемент через `document.createElement`, задаёт класс и текст через `textContent`.
- `cart.js` — корзина: чтение и запись в `localStorage`, добавление, изменение количества, удаление, расчёты через `reduce`, промокод, счётчик в шапке, вывод страницы корзины и состава заявки на `order.html`.
- `modal.js` — открытие и закрытие окна «Заказать звонок»: по кнопке, крестику, клику по фону и клавише Esc, с возвратом фокуса на кнопку.
- `validation.js` — правила проверки полей формы заявки, вывод ошибок под полями, общий статус формы и имитация отправки.
- `main.js` — общие функции `formatPrice` (7021 → «7 021 ₽») и `pluralize` («1 товар», «3 товара», «8 товаров») и запуск всех частей.

Каждая функция запуска сначала проверяет, есть ли на странице нужный элемент (`if (!list) return;`). Поэтому один набор скриптов подключён на всех страницах, и ни на одной нет ошибок в консоли.

## Массив товаров

В `js/data.js` 8 товаров с одинаковой структурой:

| Свойство | Тип | Пример | Зачем |
|---|---|---|---|
| `id` | число | `1` | уникальный номер, по нему товар ищется в корзине |
| `title` | строка | `'Polar FT4'` | название, по нему работает поиск |
| `category` | строка | `'fitness'` | категория, совпадает со значением `option` в фильтре |
| `brand` | строка | `'Polar'` | производитель |
| `price` | число | `7021` | цена, по ней сортировка и расчёт корзины |
| `oldPrice` | число или `null` | `7390` | старая цена для товаров со скидкой |
| `isAvailable` | логическое | `true` | есть ли в наличии |
| `isPopular` | логическое | `true` | показывать ли на главной |
| `image`, `imageWidth`, `imageHeight` | строка, числа | `'polar-ft4'`, `403`, `640` | имя файла фото и его размеры |
| `description` | строка | — | короткое описание для карточки |
| `features` | массив строк | `['GPS', 'Пульс']` | особенности под описанием |
| `badges` | массив объектов | `[{ type: 'hit', text: 'Хит' }]` | бейджи на фото |

Категории: `fitness` (для фитнеса), `running` (для бега), `sensors` (датчики и комплекты). Цены записаны числами, `id` не повторяются.

## Реализованные функции

**Базовая часть:**

- генерация карточек товаров через JavaScript на главной, в каталоге и на странице товара;
- поиск по названию товара;
- фильтр по категории;
- сортировка по цене (по возрастанию и убыванию) и по названию;
- сообщение о пустом результате и вывод количества найденных товаров;
- валидация формы заявки с выводом ошибок на страницу;
- безопасный вывод данных через `textContent`;
- все обработчики подключены через `addEventListener()`.

**Самостоятельные доработки** описаны в отдельном разделе ниже.

## Генерация карточек

Функция `createProductCard(product)` собирает карточку из элементов, созданных через `document.createElement`. Текст задаётся через `textContent`, классы — через `className` и `classList.add`, элементы складываются через `append`. Разметка карточки такая же, как в КР №3, поэтому стили не менялись.

`renderProducts(container, list)` очищает контейнер (`replaceChildren()`) и добавляет в него карточки по одной. В HTML вместо карточек остались только пустые контейнеры: `#catalog-list`, `#popular-list`, `#similar-list`.

## Поиск

Поле «Поиск по названию» в каталоге. Обработчик события `input` срабатывает на каждый введённый символ. Запрос очищается от пробелов по краям и приводится к нижнему регистру, затем остаются товары, у которых `title.toLowerCase().includes(query)`. Например, по запросу `polar f` находятся Polar FT4, Polar FT1 и Комплект Polar FT1.

## Фильтрация

Список «Категория» с вариантами «Все категории», «Для фитнеса», «Для бега», «Датчики и комплекты». Обработчик события `change` оставляет товары, у которых `product.category` равен выбранному значению. При значении `all` фильтр не применяется.

Дополнительно: галочка «Только в наличии» (оставляет товары с `isAvailable: true`) и параметр в адресе. Ссылки на категории в подвале ведут на `catalog.html?category=running`, и фильтр сразу выставлен на нужную категорию (`URLSearchParams`).

Поиск, фильтр, галочка и сортировка работают вместе: функция `getFilteredProducts` применяет их по очереди к одному списку.

## Сортировка

Список «Сортировка»: по умолчанию, сначала дешевле, сначала дороже, по названию. Сортируется копия массива:

```js
const sorted = [...list];
sorted.sort((a, b) => a.price - b.price);
```

Исходный массив `products` не меняется. Поэтому вариант «по умолчанию» возвращает товары в изначальном порядке. По названию сортировка идёт через `localeCompare(…, 'ru')`.

## Пустое состояние

Если ничего не найдено, вместо сетки появляется блок «Ничего не нашлось», а счётчик показывает «Найдено 0 товаров».

## Валидация формы

Форма на `order.html` помечена `novalidate`, проверку делает `validation.js`. При отправке (`submit`) вызывается `preventDefault()`, и каждое поле проверяется своим правилом из объекта `orderRules`:

| Поле | Правило |
|---|---|
| Имя | не короче 2 символов |
| Телефон | 10–11 цифр, пробелы, скобки, `+` и `-` не учитываются |
| E-mail | формат `name@example.com` (регулярное выражение) |
| Тема заявки | выбран вариант |
| Согласие | галочка отмечена |

Также проверяется, что корзина не пуста: состав заявки берётся из неё.

Ошибки выводятся под полями через `textContent`. Полю добавляется класс `form__field--error` (красная рамка) и атрибут `aria-invalid="true"`. Над кнопкой появляется общий статус «Заявка не отправлена: исправьте поля, отмеченные красным», фокус переходит на первое поле с ошибкой. После первой ошибки поле перепроверяется при вводе, и сообщение исчезает, как только значение становится корректным. `alert()` нигде не используется.

## Безопасный вывод данных

`innerHTML` в проекте не используется вообще. Все тексты — названия товаров, цены, ошибки, сообщения, запрос пользователя в пустом состоянии каталога, имя и телефон в сообщении об успешной заявке — выводятся через `textContent`.

Проверка: если ввести в поиск `<img src=x onerror=alert(1)>`, в пустом состоянии эта строка отображается как обычный текст, тег не создаётся и скрипт не выполняется.

## Самостоятельные доработки

1. **Корзина** (`cart.html`, `cart.js`). Добавить товар можно кнопкой «В корзину» в любой карточке и на странице товара. В корзине можно менять количество кнопками − и + (при нуле товар удаляется), удалить товар или очистить корзину целиком.
2. **Расчёт суммы через `reduce`.** `getCartSubtotal` считает сумму как `items.reduce((sum, item) => sum + item.price * item.qty, 0)`, `getCartCount` — общее количество товаров.
3. **Сохранение в `localStorage`.** Корзина хранится под ключом `runsmart-cart` в виде `[{ id: 1, qty: 2 }]`, промокод — под ключом `runsmart-promo`. После перезагрузки страницы или закрытия вкладки корзина остаётся. Если в хранилище испорчены данные, `getCart()` возвращает пустой массив (`try/catch`).
4. **Промокод.** На странице корзины поле «Промокод». Код `RUN10` даёт скидку 10%, она показывается отдельной строкой и учитывается в итоге и в составе заявки. Неверный код выдаёт сообщение «Промокод не найден».
5. **Счётчик товаров в шапке.** У пункта меню «Корзина» число товаров. Обновляется сразу после добавления, без перезагрузки, и меняет цвет, когда корзина пуста.
6. **Единый сценарий заказа.** Каталог → «В корзину» → корзина → «Оформить заявку» → форма. Состав и сумма на `order.html` берутся из корзины.
7. **Имитация отправки формы.** После успешной проверки кнопка на секунду становится неактивной с текстом «Отправляем…». Затем появляется сообщение «Спасибо, <имя>! Заявка подготовлена…», форма и корзина очищаются, счётчик обнуляется. «Очистить форму» убирает и все ошибки.
8. **Расширенное пустое состояние.**
   - В каталоге блок с иконкой, текстом, где повторён запрос пользователя, и двумя действиями: «Сбросить фильтры» и «Спросить консультанта» (открывает модальное окно).
   - Отдельные пустые состояния у корзины («В корзине пока пусто» со ссылкой в каталог) и у состава заявки.
9. **Обратная связь кнопок.** После нажатия «В корзину» кнопка на 1,5 секунды становится зелёной с текстом «Добавлено ✓». У товара «Нет в наличии» кнопка неактивна (`disabled`).
10. **Модальное окно на JavaScript** (`modal.js`). Окно открывается добавлением класса `modal--open`, закрывается крестиком, кликом по фону и клавишей Esc. При открытии фокус ставится в поле «Имя», после закрытия возвращается на кнопку, которая его открыла. Без JavaScript окно продолжает работать через CSS `:target`, как в КР №3.
11. **Делегирование событий.** Кнопки «В корзину» обрабатывает один обработчик на `document` через `event.target.closest('[data-add-to-cart]')`. Он работает и для карточек, созданных через JavaScript. Кнопки −, + и «Удалить» в корзине обрабатываются одним обработчиком на списке, действие и товар берутся из `data-action` и `data-id`.

## Как проверить

1. **Каталог.** Ввести `polar` — останутся только товары Polar. Выбрать категорию «Для бега» — останутся три товара. Выбрать «сначала дешевле» — цены идут по возрастанию. Ввести `xyz` — появится «Ничего не нашлось» и «Найдено 0 товаров», кнопка «Сбросить фильтры» вернёт все 8 товаров.
2. **Корзина.** В каталоге нажать «В корзину» у двух товаров — счётчик в шапке станет 2. Открыть «Корзину», нажать + и −, ввести промокод `RUN10`. Обновить страницу — корзина сохранилась.
3. **Заявка.** Нажать «Оформить заявку», затем «Отправить заявку» с пустыми полями — под полями появятся ошибки. Ввести телефон `12345` — ошибка про 10–11 цифр. Заполнить всё правильно — через секунду появится сообщение об успехе, корзина очистится.
4. **Модальное окно.** «Заказать звонок» в шапке: окно открывается, закрывается по Esc.
5. **Консоль.** DevTools → Console на всех страницах: ошибок нет.
6. **Хранилище.** DevTools → Application → Local Storage: там видны ключи `runsmart-cart` и `runsmart-promo`.
